---
title: Quickstart
description: From install to your first timeline and agent integration. Takes about five minutes.
---

Requires **macOS** (Apple Silicon or Intel) — currently the only supported platform.

<Steps>
<Step title="Install">

```bash
brew install kentoshimizu/tap/zanei
```

The formula installs a signed, notarized `Zanei.app` and puts the `zanei` command on your `PATH`.

:::note[Building from source]
See the [packaging instructions](https://github.com/KentoShimizu/zanei/blob/main/packaging/README.md).
A raw `cargo install` binary is not the distributed app bundle: a permission row added with `+`
may not persist, and a reset addressed to `dev.zanei.recorder` does not apply to it.
:::

</Step>
<Step title="Start recording">

Start the background recorder so macOS can register it and ask for the Accessibility and Input Monitoring permissions required by your capture configuration:

```bash
zanei start
```

On first setup, macOS asks for permissions one at a time: **Accessibility first, then Input Monitoring**. Respond to each dialog before continuing. `start` may exit with code 3 after the recorder starts and reports a missing permission. The daemon remains running so you can grant it. Automation is requested separately by macOS the first time Zanei contacts Chrome.

</Step>
<Step title="Grant permissions and choose content capture">

Permission dialogs identify the bundled app as `Zanei`, and **Privacy & Security → Accessibility** adds its row automatically. **Input Monitoring** may omit the row even after the dialog grant takes effect. After restarting, trust the recorder-reported `zanei doctor` result. To manage that permission from the list, use `+` and select the installed `Zanei.app`; while the permission is still reported missing, `zanei doctor --fix` opens the pane and copies that exact path.

If `start` reports a missing permission, grant it and restart the recorder so it picks up the new decision:

```bash
zanei stop && zanei start
```

Once all required permissions are granted, the first successful interactive `start` asks whether to record typed text and clipboard contents, unless this setting is already explicit in `config.toml`. Type `y` to enable it, or press Enter (the default `N`) to keep it off. The answer is saved before the recorder starts, so the question appears only once. You can change the decision later with:

```bash
zanei config set capture.text_content <true|false>
```

Then verify the recorder's own permission report:

```bash
zanei doctor
```

:::note
`zanei doctor --fix` opens a missing permission's System Settings pane and copies the path needed by the fallback. Granting is always a user action; `doctor` verifies the state enforced for the recorder itself. See the [permissions guide](/guides/permissions) for manual addition and removal details.
:::

</Step>
<Step title="Get your first timeline">

Work normally for a bit, then pull up your recent history:

```bash
zanei timeline --since 15m
```

You get a session-structured, deduplicated Markdown timeline — the same form agents consume. For raw events, use `zanei query --since 15m` instead (see [retrieving data](/guides/timeline)).

</Step>
<Step title="Connect your agent (optional)">

Place the skill file for your agent and print its MCP registration command:

```bash
zanei setup --agent claude
```

From now on, telling your agent "check what I was just working on and continue" lets it restore context from the timeline. See [agent integration](/agents) for supported agents and details.

</Step>
</Steps>

## Recording defaults

- Data is stored in a local SQLite database (`~/.local/state/zanei/store.sqlite`) and is not sent anywhere.
- Keystroke content is not recorded by default — only the fact that typing happened and the
  field type. If no choice is already saved, the first successful interactive `start` asks you to
  choose, with `N` as the default.
  Change the saved decision later with `zanei config set capture.text_content <true|false>`.
- Events are deleted automatically after 48 hours by default (configurable in [settings](/reference/config)).
- Apps and sites you don't want recorded can be excluded before they are written with [filters](/guides/filters).

:::note[If you want to stop]
`zanei pause --for 1h` pauses temporarily, `zanei stop` stops completely (data is kept), and `zanei purge --all` deletes all data.
:::
